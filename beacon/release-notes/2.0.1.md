# Beacon .NET 2.0.1

## Native loader version correction

The attempted 2.0.0 release exposed a mismatch between the native build driver's
tag-derived assembly major version and the managed profiler's pinned upstream
assembly identity. A v2 product tag made the native profiler request assembly
2.0.0.0 while the managed profiler retained 1.0.0.0, causing startup failures in
the Windows shell smoke test. No 2.0.0 Release assets were published; its tag is
retained unchanged.

The native build driver and managed projects now import the same version inputs.
Beacon product version 2.0.1 remains independent of upstream assembly/NuGet
identities. CI checks the effective MSBuild version override for both projects.

## Breaking Security log binding

This release adopts `beacon-security-log-body-v1`, pinned to specification
`d9d76e5a41d974d294bb596e06918bb954319bf6`. LogRecord Body is compact single-line
schema-v2 JSON. Only `observed_at` and `occurrence_id` move out of Body, to native
OTel event time and `attributes.event_id`. Other paths, values and nesting remain
unchanged; `source` remains in Body and attributes. There is no SIEM `message`
wrapper. Fingerprint v1 and inventory ID derivation are unchanged; retries keep
time and identity, and record budgets use final compact UTF-8 Body bytes.

Security stays experimental, opt-in, with default no-evidence filtering. Local
diagnostics retain full logical v2 events separately from the online Body.
Upgrade consumers before producers. Rollback restores Beacon 1.1.3 and its
matching full-v2 consumer. Runtime/platform and installer support are defined by
the actual release validation, not by source availability. This baseline targets
.NET 10/11 and its declared Windows .NET Framework matrix.

Platform ZIPs, NuGet archives, DEB/RPM/MSI installers, checksums, SBOM and GitHub
attestations remain the distribution scope. Public installation validation must
pass before platform acceptance is announced.
