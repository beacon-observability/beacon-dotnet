## Changes

- **Fix:** resolve Windows startup failures caused by inconsistent native and managed assembly versions. Both build paths now share the pinned upstream version inputs; see [the fix](https://github.com/beacon-observability/beacon-dotnet/pull/35).
- **Breaking:** adopt the [standard log binding](https://github.com/beacon-observability/beacon-security-spec/commit/d9d76e5a41d974d294bb596e06918bb954319bf6): compact, single-line schema-v2 JSON directly in LogRecord Body, without a SIEM envelope or `message` wrapper.

## Upgrade

Update log consumers before upgrading. Parse Body once and read the relocated fields from native metadata:

| Previous field       | Read from                                      |
| -------------------- | ---------------------------------------------- |
| Body `observed_at`   | Native LogRecord event time (`time_unix_nano`) |
| Body `occurrence_id` | LogRecord `attributes.event_id`                |

- All other field paths and values stay intact; `source` remains in Body and attributes. Schema v2, fingerprint v1, inventory IDs, opt-in Security, and default `no_evidence` filtering stay unchanged.
- Body budgets use final compact UTF-8 bytes; retries preserve event time and identity. Local diagnostics retain the complete logical v2 events separately from the online Body.
- Use **2.0.1**; no **2.0.0** Release assets were published. To roll back, restore **1.1.3** and its matching full-v2 consumer.

## Distribution

- **16 attached assets:** platform ZIPs, NuGet archive, DEB/RPM/MSI packages, installers, [checksums](https://github.com/beacon-observability/beacon-dotnet/releases/download/v2.0.1/checksums.txt), and SBOM. GitHub attestations are available for every asset.
- CoreCLR baseline: **.NET 10/11**. Security CI covers **Linux glibc x64, Windows x64, and macOS ARM64**. Other downloadable architectures do not imply broader Security coverage.
- Beacon product versions remain independent of upstream assembly and NuGet identities.
