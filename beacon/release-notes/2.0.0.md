# Beacon .NET 2.0.0

## Breaking Security log binding

Security now exports compact single-line schema-v2 JSON directly in the OTel
LogRecord Body. `observed_at` moves to native event time and `occurrence_id`
moves to the `event_id` log attribute. `source` remains in Body and attributes;
all other field paths, decoded values and nesting remain unchanged. There is no
SIEM envelope or `message` wrapper. Fingerprint v1 and the inventory ID algorithm
are unchanged. Queueing and retries retain event time and identity. Record byte
budgets and inventory partitioning use the final compact UTF-8 Body.

Security pins specification `d9d76e5a41d974d294bb596e06918bb954319bf6` and includes the exact logical, Body
and optional downstream-reference schemas in distribution provenance. Findings
retain detection-time `span_id` and numeric `trace_flags`. Findings classified
as `no_evidence` are filtered by default before local/online export; opt in with
`BEACON_SECURITY_EXPORT_NO_EVIDENCE_ENABLED=true`. Local diagnostics retain full
logical v2 events, independently of the compact online Body.

## Distribution and migration

The upstream baseline, managed assembly identities and NuGet package IDs are
independent of this Beacon product version. Do not globally replace those IDs or
versions. This source baseline targets .NET 10/11 and the declared .NET Framework
Windows matrix; platform acceptance is recorded by CI and published-artifact
validation, not inferred from source.

Update downstream consumers before upgrading the agent. Rollback to Beacon
1.1.3 with its compatible full-v2 consumer. Platform ZIPs, native installers,
checksums, SBOM and attestations remain the distribution boundary. Public
installation validation must pass before announcing platform acceptance.
