## Highlights

Beacon .NET 1.1.1 adds experimental Security telemetry, disabled by default. Enable it with `BEACON_SECURITY_ENABLED=true` to collect runtime-loaded assembly inventory and supported request-scoped source-to-sink observations.

The 1.1.0 build was not published because vulnerability auditing rejected a transitive dependency in the demo application. This release fixes that dependency without disabling auditing.

## Changes

- Add asynchronous assembly inventory with periodic OpenTelemetry Logs publication and bounded multipart records.
- Track ASP.NET Core query values through string concatenation into file reads, ADO.NET text commands, HTTP destinations and process invocations.
- Export request-deduplicated findings without raw request values, SQL or shell scripts, using Beacon Security schema 2 and fingerprint version 1.
- Add separately enabled, bounded local diagnostic snapshots and an optional finding evidence file.
- Bundle pinned Security contracts and record their versions, specification commit and digests in artifact metadata.
- Pin the demo application's transitive PKCS dependency to the lowest patched 9.x version, 9.0.21.
- Fix vulnerable build/test dependency references and distinguish SDK provenance stamps from generated-code changes.
- Move macOS build and validation jobs to macOS 15 while preserving the native library's macOS 14 deployment minimum.

## Compatibility and Limitations

- Based on OpenTelemetry .NET Automatic Instrumentation `v1.17.0`; Beacon product and upstream assembly versions remain independent.
- Security stays experimental and opt-in. Native flow/export tests cover .NET 8, 9 and 10 on Linux glibc x64, Windows x64 and macOS ARM64. .NET Framework runtime behavior and cross-AppDomain identity remain unverified; Security acceptance is not claimed for the additional archive targets.
- Inventory contains observed CLR assembly identities, not a complete NuGet dependency graph. Modeled flows are not confirmed exploits. See the [Security coverage, configuration and budgets](https://github.com/beacon-observability/beacon-dotnet/tree/v1.1.1/beacon/security).
- Local output requires `BEACON_SECURITY_LOCAL_OUTPUT_ENABLED=true` separately; standard OpenTelemetry configuration controls transport and resource identity.
- MSI, DEB and RPM packages are not yet Authenticode-signed or distributed through signed package repositories; verify GitHub artifact attestations before installation.
- End-to-end DataKit ingestion and production performance acceptance are outside the verified release scope.

See the [documentation](https://github.com/beacon-observability/beacon-dotnet/tree/v1.1.1/docs) for installation, configuration, management and troubleshooting.
